# Лабораторная работа №2 - Основы ООП

## Цель работы

Реализовать иерархию классов игровых объектов с наследованием, инкапсуляцией и двумя абстрактными интерфейсами.

## Описание работы

Иерархия повторяет схему из задания:

- `GameObject` - базовый класс с идентификатором, именем и координатами;
- `Unit` - юнит с запасом здоровья;
- `Building` - постройка с флагом `built`;
- `Archer` наследует `Unit` и реализует `Attacker` и `Moveable`;
- `Fort` наследует `Building` и реализует `Attacker`;
- `MobileHouse` наследует `Building` и реализует `Moveable`.

Идентификатор объекта не генерируется внутри класса: он приходит параметром в `__init__` и там же сохраняется в закрытое поле `__id`. За уникальность номеров отвечает код, который создаёт объекты, - в `main.py` номера заданы явно.

## Структура проекта

Исходный код находится в `src/`, по одному файлу на класс. Запуск:

```bash
cd lab02/src
python main.py
```

## Что проверяет main.py

- идентификатор, имя и координаты объекта;
- атака лучника и крепости через общий интерфейс `Attacker`;
- смерть юнита: здоровье не уходит ниже нуля, мёртвый лучник не атакует и не двигается;
- недостроенная крепость не стреляет, после вызова `build()` начинает;
- перемещение лучника и мобильного дома.

## Принципы ООП

- **Инкапсуляция:** поля `__id`, `__hp`, `__x`, `__y` закрыты, доступ идёт через `getId()`, `getHp()`, `getX()`, `getY()`.
- **Наследование:** `Archer` → `Unit` → `GameObject`, `Fort` → `Building` → `GameObject`.
- **Полиморфизм:** в `main.py` лучник и крепость лежат в одном кортеже и вызываются через `attacker.attack(enemy)`.
- **Абстракция:** `Attacker` и `Moveable` - абстрактные классы с методами `@abstractmethod`.

## Результат

Реализовано 8 классов. Программа запускается командой `python main.py` из директории `lab02/src` и выводит результаты проверки атаки, смерти юнита, постройки крепости и перемещения объектов.
